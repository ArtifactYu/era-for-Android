## 一次完整文字游戏流程

选择 **eraRPG**，完成建档、角色创建、课题选择、研究操作、跨日自动存档、退出重进读档、申请毕业、到达游戏明确的正常毕业结局，再跨日保存并重进确认学位记录。完整测试共 122 次输入，关键检查全部通过。俄罗斯方块仅列入全站有限兼容测试，未用作完整流程案例。

路线依据游戏公开脚本辅助规划，研究序列全部通过游戏菜单输入，没有直接修改游戏变量或存档。此次选择不死生物研究路线。该游戏在跨日等指定节点自动保存，普通休息一小时不会保存；毕业脚本保存与授予学位的先后顺序也需要注意，因此测试在获得学位后再次跨日，并实际读档确认。

## 本轮发现与修复

- 旧中文配置名称未被识别，导致子目录脚本和初始化函数缺失。
- 同一游戏中混用旧编码时的文件读取，以及读取失败后被误当作有效缓存。
- CSV 诊断误使用 ERB 目录的问题。
- PuchiEmuera 的 FONTEDGE、FADE、SHAKE 与 FIXED 图片语法，包含分组、透明度、翻转及清行处理。
- ONEINPUT 的即时单键输入；普通 INPUT 仍可输入多位数字再确认。
- 横屏软键盘使确认按钮超出可见区域。文字输入时临时收起数字区，并保持焦点直到点击完成。
- 关闭鼠标支持的游戏被错误地统一视为数字输入。现在仍按实际指令显示继续、文字输入和数字输入，独立样例已在正式安卓包中验证。

保留此前修复的文件名大小写、ZIP 文件名编码、旧函数重名、连续切换游戏的退出时序，以及定时动画与输入并发的打印缓冲问题。测试驱动也修正了等待动画后的状态更新和过快点按；这些驱动问题没有计作应用兼容故障。

麻将测试会按当前随机手牌选择有效数字选项。测试工具排除了引擎调试链接，避免将它误当成游戏菜单输入。

## 界面、图片和存档

中性自编游戏用于验证横竖屏切换、真实双击侧栏、连续输入 11、左右布局、设置持久化、实际文字显示比例、图片开关及标准存读档。兼容性实验室验证旧编码、固定图片显隐、淡入淡出、震动指令、清行和单键输入，图片结果另做像素检查。

存储模块 10 项检查通过；系统文件选择器的 3 项备份检查通过，包括恢复前保留原档副本。详细检查项目在 `测试数据.json`。界面展示截图采用自主编写的中性游戏。

## 安装包验证

Android 8.0+，ARM64 与 x86_64，目标 SDK 36；版本 1.1.0 / code 2，可覆盖本项目 1.0。正式签名 APK 实际安装后完成升级保留游戏库及读档交互抽查。v2/v3 签名校验通过。

24 个原生库的 ELF LOAD 段符合 16 KB 对齐要求，APK 通过 `zipalign -P 16` 检查。原生库采用压缩包装，安装时解压；其 ZIP 内数据无需逐库 16 KB 对齐。这与 [Android 官方页面大小说明](https://developer.android.com/guide/practices/page-sizes#update-packaging) 一致。未在 16 KB 页面实机上运行。

正式包未启用应用调试，`/diagnostics` 和 `/choices` 测试接口返回 404，无令牌访问受保护接口返回 403。AOSP userdebug 系统可强制开启 WebView 调试，这是系统行为，参见 [Chromium 实现](https://chromium.googlesource.com/chromium/src/+/875e15c94d995212867016abd2651d71f1c9f4b4/android_webview/glue/java/src/com/android/webview/chromium/SharedStatics.java)。

## 覆盖边界

实际运行环境为 Android 15 / API 35 的 x86_64 模拟器。ARM64 已编译打包，未连接 ARM64 实机。全站测试是有限的启动和交互序列；只有 eraRPG 完成上述明确结局流程，没有遍历全部游戏的所有剧情、随机事件与长期分支，不能承诺任意游戏绝无 bug。

Windows DLL 插件、音频后端和桌面词典弹窗未实现。标准存档可备份，自定义脚本写在其他位置的数据可能不在备份范围。外部目录导入后复制到应用空间。游戏运行和保存均在本机，网络权限用于令牌保护的本机回环通信。APK 与源码包不附带第三方游戏。
